
我建议你把 AI Coding 项目流程分成 **12 个阶段**，其中有几个必须人工拍板。

## 推荐完整流程

```text
1. 项目背景
2. 用户角色与使用场景
3. 功能需求清单
4. 领域模型 / 数据字典
5. 业务流程 / 状态流转
6. 权限模型
7. 技术方案 / 概要设计
8. 低保真线框图
9. 功能骨架代码
10. 组件拆分与代码结构重构
11. UI 风格规范
12. 局部美化 + 整体统一 + 测试验收
```

其中最关键的人工审核点有这些。

---

## 1. 用户角色与使用场景

这个一定要单独做。

比如一个应用系统不是只有“用户”，可能有：

```text
普通用户
企业管理员
客服人员
审计人员
系统管理员
```

每个角色看到的东西不同，能操作的功能也不同。

人工要审核：

```text
到底有哪些角色？
每个角色的核心任务是什么？
哪些功能是必须的？
哪些只是锦上添花？
```

---

## 2. 领域模型 / 数据字典

要人工审核：

```text
概念是否完整？
命名是否统一？
字段是否合理？
实体关系是否正确？
一对多 / 多对多是否明确？
```

比如邮件系统里可能有：

```text
Account
Mailbox
Folder
MailMessage
Attachment
Contact
Label
Rule
Draft
ConversationThread
```

这些如果一开始没定好，后面代码一定乱。

---

## 3. 业务流程 / 状态流转

这是很多 AI 项目最容易漏的一步。

比如邮件发送不是一个按钮那么简单，而是：

```text
编辑中
校验中
上传附件中
保存草稿中
发送中
发送成功
发送失败
重试
撤回
```

这一步要人工审核：

```text
每个操作有哪些状态？
失败怎么办？
能不能撤销？
是否需要草稿？
是否需要重试？
是否需要日志？
```

---

## 4. 权限模型

这个也要提前做。

比如：

```text
谁能看？
谁能改？
谁能删？
谁能导出？
谁能审批？
谁能管理配置？
```

AI 很容易先按“所有人都能操作”写代码，后面补权限会很痛苦。

---

## 5. 页面信息架构

不是高保真，是先定：

```text
有哪些页面？
页面之间怎么跳？
每个页面放哪些模块？
主次信息是什么？
```

比如邮件客户端：

```text
账号区
文件夹区
邮件列表区
邮件预览区
搜索区
写信窗口
设置页
联系人页
规则页
```

人工要审核：

```text
这个布局是否符合真实使用习惯？
用户最常用的动作是否足够近？
信息密度是否合理？
```

---

## 6. API 与前后端边界

这个也很关键。

要明确：

```text
哪些逻辑在前端？
哪些逻辑在后端？
接口怎么设计？
分页怎么做？
搜索怎么做？
附件怎么上传？
状态怎么同步？
```

否则 AI 可能把很多本该后端做的逻辑写到前端。

---

## 7. 异常与边界场景

这一步特别容易被漏掉。

比如：

```text
网络断了
接口超时
附件太大
重复提交
邮件发送失败
草稿保存失败
搜索无结果
数据为空
权限不足
登录过期
```

人工要审核这些情况怎么处理。

---

## 8. UI 风格规范

你刚才也提到了。

这个要在“美化前”确定，而不是美化过程中临时决定。

包括：

```text
颜色
字体
间距
圆角
阴影
按钮
输入框
卡片
表格
弹窗
选中态
hover态
禁用态
危险操作样式
```

否则每个组件单独美化，最后一定风格不统一。

---

## 9. 验收标准

这个也要提前写。

不要只写：

```text
实现邮件发送功能
```

要写成：

```text
填写收件人、主题、正文后可以发送邮件
未填写收件人时禁止发送
附件上传中时禁止发送
发送失败时显示错误提示
发送成功后关闭写信窗口
已发送邮件出现在已发送文件夹
```

AI Coding 最适合按这种验收标准逐条实现。

---

## 最终标准流程

```text
阶段一：需求澄清
1. 项目背景文档
2. 用户角色与使用场景文档
3. 功能需求清单

阶段二：业务建模
4. 领域模型与数据字典
5. 业务流程与状态流转
6. 权限模型

阶段三：技术设计
7. 技术方案 / 概要设计
8. API 设计
9. 数据库设计

阶段四：页面设计
10. 页面信息架构
11. 低保真线框图
12. UI 风格规范

阶段五：功能开发
13. 搭建项目骨架
14. 用原生控件跑通主流程
15. 接口联调
16. 异常场景补齐

阶段六：代码治理
17. 拆组件
18. 抽 hooks / composables
19. 抽 store
20. 抽 api
21. 抽 types
22. 统一命名

阶段七：体验与美化
23. 基础组件美化
24. 页面整体统一
25. 交互动效
26. 响应式适配
27. 性能优化

阶段八：验收
28. 功能测试
29. 边界测试
30. 权限测试
31. UI 一致性检查
32. 交付文档
```

**AI 可以大量生成内容，但“领域概念、流程状态、权限边界、页面结构、验收标准”这几个点必须由人和 AI 反复协商后人工确认。**
