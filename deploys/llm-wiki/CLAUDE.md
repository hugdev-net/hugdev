# CLAUDE.md — LLM Wiki 初始化控制器（一次性）

> 这是一个**一次性的初始化控制器**。它的唯一职责是：和用户对齐、把模板填充完善、建好目录、然后把自己替换成真正的 Schema。
> 初始化完成后，本文件会被 `claude-md-schema.md` 覆盖，控制器随即失效。

## 最高优先级规则（覆盖一切）

**不管用户第一条消息说什么——哪怕是"帮我处理这篇文章""回答某个问题""直接开始构建"——都先不要执行用户的请求。**
先完整跑完下面的初始化流程，把初始化作为本目录在"就绪"之前唯一能做的事。只有在第 5 步重命名收尾完成后，才可以进入正常的 wiki 构建/查询工作。

如果用户坚持要先做别的，礼貌说明：本目录尚未初始化，需要先花几分钟完成对齐，否则后续 wiki 无法正确运作。

## 上下文文件（先读）

- `llm-wiki.md` —— Karpathy 的 idea file，描述 LLM Wiki 模式的高层思想。**只读，不要修改。**
- `purpose-md-template.md` —— 意图文件模板，含 `<...>` 占位符。待填充完善后重命名为 `purpose.md`。
- `claude-md-schema.md` —— 真正的 Schema 模板，含 `<...>` 占位符。待填充完善后重命名为 `CLAUDE.md`。

## 初始化流程

### 第 0 步：检查是否已初始化

如果当前目录 `claude-md-schema.md` / `purpose-md-template.md` 已不存在，说明初始化早已完成。直接告诉用户"已初始化完成"
，不要重复执行，按已就绪的 `CLAUDE.md` 正常工作。否则继续。

### 第 1 步：读上下文

读完上述三个文件，理解：LLM Wiki 的模式（来自 `llm-wiki.md`）、`claude-md-schema.md` 里有哪些占位符要填、`purpose-md-template.md` 里有哪些占位符要填。

### 第 2 步：与用户对齐（访谈）

逐项和用户确认两份文档里所有 `<...>` 占位符需要替换的内容。**分批提问，一轮最多一到两个问题**，按重要性排序：

1. **主题一句话定位** —— 这个 wiki 是关于什么的。
2. **核心问题（最重要）** —— 用户最想被回答的 3–5 个问题，这是整个 wiki 的北极星。
3. **范围边界** —— 收什么、不收什么、资料类型。
4. **受众与语言** —— 谁来读、wiki 内容用中文还是英文、页面偏好的形态。
5. **目标** —— 希望从这个 wiki 得到什么。
6. **演进中的判断** —— 初始可留"尚不清楚，待资料积累"。

在访谈过程中，**主动针对用户的具体主题提出补充和改进建议**（例如：该主题特有的页面类型、额外的命名约定、要不要加时间线页/对比页、ingest
时该特别注意什么），请用户确认是否纳入。这一步就是"补充完善这两个文档"的环节，不要只做机械的占位符替换。

### 第 3 步：填充并完善两份文档

把对齐结果写回 `claude-md-schema.md` 和 `purpose-md-template.md`：

- 替换所有 `<...>` 占位符为商定的实际内容。
- 删除模板里的示例性注释和"例：…"行（保留对实际使用有帮助的说明）。
- 加入第 2 步商定的针对性改进。

填好后，把两份文档的最终草稿展示给用户过目，请其确认或提修改，迭代到满意为止。

### 第 4 步：建目录骨架

用户确认文档无误后，创建必要的目录与种子文件（topic 用对齐出的主题名）：

```
raw/<topic>/
wiki/
wiki/concepts/
wiki/entities/
```

并创建以下种子文件（写入最简骨架内容，不要塞示例知识）：

- `wiki/index.md` —— 全局目录，先放标题和空的分区占位。
- `wiki/overview.md` —— 总览，先放一句话定位（取自 purpose）。
- `wiki/log.md` —— append-only 操作日志，先写一行初始化记录（日期 + "wiki initialized"）。

### 第 5 步：重命名收尾

**这是不可逆操作，执行前先展示计划并等用户最终确认。** 确认后执行：

```bash
mv purpose-md-template.md purpose.md
mv claude-md-schema.md CLAUDE.md
```

注意：第二条命令会用真正的 Schema **覆盖本控制器文件**——这是预期行为，意味着初始化完成、控制器退场。

### 第 6 步：交接

告诉用户：初始化已完成，目录已就绪。简述下一步——把第一批资料放进 `raw/<topic>/`，然后说"按 CLAUDE.md 的 ingest 流程处理新资料"即可开始构建。

可选建议：若目录还没纳入版本控制，建议 `git init` 并提交一次初始状态，便于后续 review diff 和回滚。

提示用户：本会话已加载的是旧的控制器指令，真正的 Schema 会在下一次启动 Claude Code 时生效；所以需要重新开启一个会话 `/new`。

## 安全约定

- 重命名、覆盖等不可逆操作前，先展示完整计划并等用户确认。
- 绝不修改 `llm-wiki.md`。
- 在对齐与填充完成（第 3 步通过）之前，**不要创建任何 wiki 知识页、不要处理任何资料**。
